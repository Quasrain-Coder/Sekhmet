# Sekhmet — GTO Bot L4.5 · 翻后范围收窄 + 多人池建模 · 设计文档

> 2026-10-05 · 迭代 #6：gto_bot 头部自述的两个已知简化——"对手翻后范围只按翻前故事推断，不随对手行动收窄"、"多人池只对最后加注者建模"——本包修掉。这是 bot 强度与真实感（对手收窄范围是任何人类玩家的基本操作）的双升级。

## 1. 背景

- `infer_opponent_range()`：翻后从 pot 大小猜翻前故事（raised vs limped），对手翻后的下注/加注完全不缩小范围——对手连下三条街，bot 还当他是"翻前 RFI 全范围"
- `_equity_vs_opponent()`：多人池只建模 `last_aggressor`（或第一个活跃对手），其余对手视而不见
- 训练器迭代 #2/#5 也骑在这套推断上——bot 变准，随机题的参考动作同步变准

## 2. 范围

**做**：
- `equity.py` 新增：
  - `postflop_aggression_count(state, opp_seat)`：对手本手 BET/RAISE/ALL_IN 总数，减去从 `current_bet` 档位推断的翻前加注数（≤BB:0 / ≤4BB:1 / >4BB:2）——round_history 无街标记，此为文档化近似
  - `narrow_range(rng, level)`：按图频率收窄——level 1 保留 freq≥0.3 的核心，level ≥2 保留 freq≥0.7；收窄为空则回落原范围
- `infer_range_for_opponent(state, hero_seat, opp_seat)`：把现有"最后加注者"推断泛化为指定对手（各自的位置桶/各自档位），翻后按 aggression 收窄
- `gto_bot._equity_vs_opponent`：遍历所有活跃对手分别算 equity 取 **min**（多人池必须打败所有人），建模目标数上限 3（防 9 人桌性能放大）
- 测试：收窄函数单调性（level 越高 combo 越少）、aggression 计数、多人 min 语义、单人行为不回归（test_gto_bot 现有 31 例为准，故意的行为变化逐条更新并注明）

**不做**（明确排除）：
- 贝叶斯范围更新（按对手 CALL/FOLD 具体动作删组合）——按 aggression 分级收窄已是"行为感知"的一阶近似
- 对手风格分层（紧凶/松弱按 StatsTracker 分流收窄速度）——留待与 RL bot 一起做
- >3 个对手的完整建模（边缘场景，性能性价比低）

## 3. 实现要点

- 收窄只作用于**翻后**：翻前图本身就是按档位选的，双重收窄会过度紧
- `fold_to_bet` 等已平滑比率不参与——收窄用"本手行动"，跨手风格是另一个维度
- min-equity 让多人池 bot 变谨慎（此前只看最后加注者，慢转可被其他对手轻松击败）——预期 L4 在多路 pots 的 fold 频率上升，属正确方向
- 单人池（heads-up）路径等价重构：收窄 level 0 时范围与旧行为完全一致，test_gto_bot 的 HU 用例应零变化

## 4. 测试与 CI

- `tests/test_equity.py` 增补：narrow_range 单调/空回落、aggression 计数（翻前加注扣减）、infer_range_for_opponent 对非加注者座位也能出范围
- `tests/test_gto_bot.py`：现有用例跑通；多路场景的新行为新增 1–2 例（三路池 equity 取 min → 面对 0.5 底池注更倾向弃牌）
- CI 无需改动
